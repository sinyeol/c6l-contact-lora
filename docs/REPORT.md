## 1. 시스템 구성

```
 [버튼1] [버튼2]                                     ┌──────────────────────────┐
     │      │  (무전압 접점, Grove 케이블)            │ 태블릿·PC 브라우저 앱      │
 ┌───▼──────▼───┐  LoRa 922.1MHz  상태 패킷  ┌──────┴───────┐  USB (Web Serial)      │
 │ 송신기 C6L   │ ─────────────────────────▶ │ 수신기 C6L   │ ─────▶ 25칸 READY/STANDBY │
 │ ID 1~25      │ ◀───────────────────────── │ ID 0 (GW)    │                         │
 │ OLED: READY  │   ACK (수신기가 저장한 상태) │ OLED: on n/25│ ··· Wi-Fi AP C6L-GW (선택)│
 └──────────────┘                            └──────────────┘  http://192.168.4.1     │
                                                                └──────────────────────────┘
```

- **펌웨어는 하나뿐**입니다. 본체에 저장한 ID 가 역할을 정합니다: 0 은 수신기, 1~25 는 송신기입니다.
- **송신기**는 버튼(접점) 2개로 READY/STANDBY 상태를 정하고 LoRa 로 보냅니다.
- **수신기**는 받은 상태를 저장한 뒤 ACK 로 송신기에 되돌려 주고, USB 로 25대 상태를 1초마다 앱에 보냅니다.

## 2. 동작

| 상황 | 송신기 OLED | 앱(해당 ID 칸) |
|---|---|---|
| 송신기 전원 켬 | `ID 05` / (빈칸) | **STANDBY**(빨강) |
| 1번 버튼 누름 | `ID 05` / **READY**(큰 글씨) | **READY**(초록), 손을 떼도 유지 |
| 2번 버튼 누름 | `ID 05` / (빈칸) | **STANDBY**(빨강), 손을 떼도 유지 |
| 송신기 전원 끔 | — | 8초 안에 READY·STANDBY 모두 **OFF**(칸이 흐려지고 `끊김`) |

- **동기화:** 송신기 OLED 의 READY 는 수신기가 READY 를 저장했다고 ACK 로 되돌려 준 때만 뜹니다. 그래서 송신기 화면이 곧 수신기와 앱에 들어간 상태입니다.
- **수신기 비콘:** 수신기는 3초마다 살아 있는 송신기들의 상태를 담은 비콘을 보냅니다. 송신기는 자기 칸을 보고 READY 표시와 링크를 정합니다.
- **링크가 끊기면:** 8초 동안 비콘도 ACK 도 못 받으면 셋째 줄이 `link --` 가 되고, READY 표시도 지웁니다.
- **누른 횟수:** 앱 칸 오른쪽의 `×N` 은 버튼별로 누른 횟수입니다. 255 다음은 0 이고, 송신기를 재부팅하면 0 부터 다시 셉니다.

| 시간 값 | 값 |
|---|---|
| 하트비트(ACK 없음, 변화가 없어도 보내는 주기) | 3초 + 0~0.5초 |
| 수신기 비콘 | 3초 + 0~0.3초 |
| 꺼짐 판정(수신기·앱) / link lost(송신기) | 8초 |
| 누름 ACK 대기 | 300ms |
| 누름 재전송 | 50~250ms×시도 횟수로 7번, 그래도 안 되면 다음 하트비트가 상태를 실어 보냄 |
| 채널 점유(25대) | 약 33%(하트비트 32% + 비콘 1.3%) |
| 앱 갱신 | 수신 즉시 + 1초마다 |

## 3. 하드웨어·배선

**Unit C6L:**
- ESP32-C6 + SX1262(LoRa), OLED 64×48, IO 확장칩 PI4IOE5V6408, 전원은 USB-C 5V
- 핀은 Meshtastic `m5stack_unitc6l` 정의와 Stamp C6LoRa 회로도 기준입니다.

**송신기 배선(Grove HY2.0-4P):**

| 선 | 신호 | 연결 |
|---|---|---|
| 흰색 | G4 | 1번 버튼(READY) |
| 노란색 | G5 | 2번 버튼(STANDBY) |
| 검은색 | GND | 두 버튼의 공통 |
| 빨간색 | 5V | **연결하지 않음** |

**주의:**
- **무전압 접점만** 연결합니다(내부 풀업 3.3V). 외부 전압을 걸거나 5V 로 풀업하면 안 됩니다.
- **선이 길면:** 직렬 1kΩ + GND 쪽 100nF 를 달거나, 포토커플러로 분리합니다.
- **안테나:** 동봉 LoRa 안테나는 868MHz 용입니다. 국내에서는 915~923MHz 안테나를 권장하며, 바꾸면 펌웨어의 `ANT_GAIN_DBI` 를 고칩니다.

## 4. 설치·설정

### 4.1 펌웨어 굽기

패키지의 `firmware/` 에 이미지가 두 개 있습니다.

| 파일 | 주소 | 용도 |
|---|---|---|
| `c6l-contact-lora-v1.0-full-0x0.bin` | `0x0` | **새 기기**(부트로더·파티션·앱 전체). NVS 까지 덮어써 ID 가 지워지므로 굽고 나서 ID 를 정합니다. |
| `c6l-contact-lora-v1.0-app-0x10000.bin` | `0x10000` | **업데이트**(앱만). 저장된 ID 를 유지합니다. |

**크롬·엣지로 굽기(설치 없음):**
1. https://espressif.github.io/esptool-js/ 를 엽니다.
2. **Connect** 를 누르고 C6L 포트(`USB JTAG/serial debug unit`)를 고릅니다.
   - 연결이 안 되면 측면 버튼을 녹색 LED 가 빨강으로 바뀔 때까지 누르고 있다가 뗍니다(다운로드 모드).
3. 새 기기면 **Erase all** 을 켭니다. 주소와 파일은 위 표대로 넣고 **Program** 을 누릅니다.
4. 끝나면 USB 를 뺐다 꽂습니다.

**명령줄(arduino-cli):**
```bash
arduino-cli compile --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc,PartitionScheme=no_fs --export-binaries .
arduino-cli upload  --fqbn esp32:esp32:esp32c6:CDCOnBoot=cdc,PartitionScheme=no_fs -p <포트> .
```
빌드 환경: arduino-esp32 3.3.12, RadioLib 8.0.0, U8g2 2.36.19, arduino-cli 1.5.1.

### 4.2 ID 정하기

**본체 버튼:**
1. 2초 길게 누르면 설정 모드가 됩니다(`SET tap=+1`).
2. 짧게 누를 때마다 +1 입니다. 25 다음은 `GW`(수신기)입니다.
3. 다시 2초 길게 누르면 저장하고 재부팅합니다.

**시리얼(115200):**
- `id 0`(수신기) 또는 `id 1`~`id 25` 를 보내면 저장하고 재부팅합니다.
- 그 밖의 줄을 보내면 `id=… radio=… link=…` 상태를 돌려줍니다.

### 4.3 브라우저 앱 (USB, 와이파이 없이)

1. 인터넷이 될 때 쓸 기기에서 **https://sinyeol.github.io/c6l-contact-lora/web/** 을 **한 번** 엽니다. 태블릿은 "홈 화면에 추가"를 합니다.
2. 수신기를 USB 로 연결하고 **[USB 연결]** → 수신기 포트를 고릅니다. 다음부터는 저절로 연결되고, 다시 꽂아도 붙습니다.
3. 그 뒤로는 **인터넷·와이파이 없이** 열립니다. 서비스워커가 페이지·아이콘·보조 라이브러리를 저장해 둡니다.

PC 는 패키지의 `web/index.html` 을 바로 열어도 됩니다.

| 기기·브라우저 | 지원 |
|---|---|
| PC 크롬·엣지 | ✅ (사무실 PC 에서 확인) |
| 안드로이드 크롬 | 148+ 와 Android 17 은 Web Serial, 그보다 낮으면 WebUSB 보조 라이브러리 — **실기기 미시험** |
| iPad·iPhone(Safari) | ❌ (Web Serial·WebUSB 미지원) |

### 4.4 수신기 Wi-Fi 페이지 (선택, 미검증)

수신기가 AP **`C6L-GW` / 비밀번호 `c6l-12345`** 를 띄웁니다. 휴대폰을 붙여 **http://192.168.4.1** 을 열면 같은 화면이 나옵니다. 비밀번호는 공개 저장소에 있으니, 필요하면 `c6l-contact-lora.ino` 맨 위의 `AP_PASS` 를 바꿉니다.

### 4.5 배터리로 쓸 때 (송신기)

**계산식:** 사용 시간(h) = 표기 용량(mAh) × 3.7V ÷ 5V × 변환 효율 0.85 ÷ 소비 전류(mA)
- 보조배터리 용량은 보통 셀 전압(3.7V) 기준입니다. 5V 로 올리면서 손실이 생겨, 실제로 쓸 수 있는 양은 표기의 약 63% 입니다.
- 소비 전류는 두 가지로 계산했습니다.
  - **85mA:** M5Stack 공식 측정값(LoRa 수신 대기, USB 5V)입니다. 보수적인 값입니다.
  - **50mA:** 이 펌웨어 기준 추정값입니다(CPU + LoRa 상시 수신 + OLED, Wi-Fi 끔). **실측이 필요합니다.**

| 표기 용량 | 85mA | 50mA |
|---|---|---|
| 2,000mAh | 약 15시간 | 약 25시간 |
| 3,000mAh (18650 1개 + 승압) | 약 22시간 | 약 38시간 |
| 5,000mAh | 약 37시간 | 약 63시간 |
| 10,000mAh | 약 74시간 | 약 126시간 |
| 20,000mAh | 약 148시간 | 약 252시간 |

- **보조배터리 자동 꺼짐:** 대부분 50~100mA 아래에서 몇십 초 뒤 출력을 끕니다. **저전류(IoT) 모드나 항상 켜짐을 지원하는 제품**을 씁니다.
- **정확한 값:** USB 전류 측정기로 실제 전류를 재서 위 식에 넣습니다.
- **더 오래 쓰려면:** OLED 를 자동으로 끄고 CPU 를 저전력 대기로 두면 20mA 안팎까지 낮출 여지가 있습니다(미구현).

## 5. 국내 전파 규정 대응

| 기준 | 펌웨어 |
|---|---|
| 채널 920.9~923.3MHz, 200kHz 간격 | **922.1MHz** 고정, 범위나 격자를 벗어나면 `static_assert` 로 빌드 실패 |
| EIRP 920.9~921.9MHz 10dBm / 922.1~923.3MHz 14dBm | 10dBm + 안테나 3dBi = **13dBm**, `TX_DBM + ANT_GAIN_DBI` 가 상한을 넘으면 빌드 실패 |
| LBT: 송신 전 5ms 이상 감지, -65dBm 이하일 때만 송신 | `krTransmit()`: 순간 RSSI 를 5.5ms 동안 확인(송신기·수신기 ACK 공통) |
| 송신 4초 이내, 송신 뒤 50ms 이상 휴지 | 패킷 약 36ms, 송신 뒤 50ms 쉼 |

- **빌드 차단 확인:** 868.1MHz, 922.0MHz, 출력 14dBm, 921.1MHz@13dBm 은 모두 빌드가 막혔습니다.
- **실행 중 변경:** 주파수를 바꾸는 명령은 없습니다.
- **수치 출처:** LoRaWAN KR920 규격, TTN, 국내 논문 같은 2차 자료입니다. 현행 **무선설비규칙 원문 대조**와 기기 자체의 **KC 적합성평가 여부**는 아직 확인하지 않았습니다.

## 6. 통신 규격

**LoRa 설정:** SF7, BW125k, CR4/5, 프리앰블 8, private sync(0x12), TCXO 3.0V(DIO3), RF 스위치는 DIO2.

| 패킷 | 바이트 |
|---|---|
| 누름(송신기 → 수신기, ACK 요청) | `C6 01 id seq bits cnt1 cnt2` — bits 1=READY, 2=STANDBY |
| 하트비트(송신기 → 수신기, ACK 없음) | `C6 03 id seq bits cnt1 cnt2` |
| ACK(수신기 → 송신기) | `C6 02 id seq bits` — bits 는 수신기가 저장한 상태 |
| 비콘(수신기 → 전체) | `C6 04` + 7바이트: 송신기 25대 × 2비트(0=꺼짐·모름, 1=READY, 2=STANDBY), `proto.h`, 호스트 시험 `tools/test_proto.cpp` |

**수신기 USB 출력(115200):**
- `S [ … ]`: 25칸 상태 JSON. 칸마다 `null` 또는 `{"a":경과초,"b":비트,"c1":1번 횟수,"c2":2번 횟수,"r":RSSI}`. Wi-Fi 의 `/s` 도 같은 형식입니다.
- `rx id=5 seq=2 bits=1 c=1/0 rssi=-12`: 받은 패킷 로그

**송신기 로그:**
- `tx ok seq=… bits=… synced=…`: ACK 수신
- `link lost (비콘·ACK 없음)`: 8초 동안 수신기 소식 없음
- `press ACK 7회 실패 — 하트비트로 전달`: 누름 ACK 실패(상태는 하트비트로 감)
- `radio init try N …`: LoRa 초기화 재시도. 실패하면 3번까지 다시 시도합니다.

## 7. 검증 결과 (2026-11-09, 실기기)

**펌웨어·하드웨어:**
- **굽기:** 사무실 윈도우 PC 크롬(esptool-js)에서 굽고 검증(`Hash of data verified`)했습니다. 이후 업데이트는 포트 선택 없이 진행했습니다.
- **초기화:** `radio=0`(IO 확장칩·SX1262·TCXO·RF 스위치 정상)이었습니다. 새 모듈 첫 부팅에서 `-2` 가 한 번 났고, 이후 리셋 6번은 모두 정상이어서 재시도를 추가했습니다.
- **OLED:** 표시가 정상이고, 사용자 요청으로 180도 회전했습니다.
- **ID 설정:** 버튼과 시리얼(`id N`) 모두로 저장했고, 재부팅 뒤에도 유지됩니다.

**링크·동작:**
- **링크:** 송신기 `tx ok … synced=2` ↔ 수신기 `rx id=…`(RSSI 0~-13dBm, 근거리)
- **래치:** 1 → 2 → 1 을 누르자 READY 가 유지되고 앱에 초록 READY 가 떴습니다. ACK 로 되돌린 상태(`synced`)가 송신기 상태와 같았습니다.
- **국내 규정 LBT 적용 후에도** 링크는 정상이었습니다.
- **꺼짐 판정 8초 실측(하트비트·비콘 방식):** 송신기 05 의 USB 를 뽑자, 마지막 수신 뒤 **8.0초**에 수신기·앱이 끊김으로 바꿨습니다. 뽑은 순간부터 재면 4.5~8초입니다(하트비트 간격 3~3.5초 안에서 달라짐). 송신기가 재시작한 뒤에는 2.1초 만에 다시 살아남으로 표시됐습니다.
- **비콘 동기화:** 송신기가 누르지 않을 때는 `tx ok` 없이(하트비트에는 ACK 없음) 비콘만으로 `link=ok`·STANDBY 동기화를 유지했습니다(ID 05·18).
- **USB 신호 순서:** 앱이 연결할 때마다 수신기를 재부팅시키던 문제를 찾아 고쳤습니다. RTS 를 먼저, DTR 을 나중에 내리는 순서만 리셋이 없습니다.
- **세 번째 모듈(송신기, 처음 ID 01 → 지금 ID 18):** v1.0 전체 이미지를 굽고(`Hash of data verified`) 시리얼 `id 1` 로 설정했습니다. 이후 본체 버튼으로 18 로 바뀌었고, 최신 펌웨어로 업데이트했습니다. `id=1 radio=0` 이었고, 수신기가 꺼진 상태여서 `link lost` 로 표시됐습니다(정상). 수신기를 켠 뒤의 링크는 아직 확인하지 않았습니다.

**앱:**
- **GitHub Pages 주소:** 권한을 받은 포트에 자동 연결되고, 25칸을 갱신합니다.
- **오프라인:** 한 번 연 뒤 네트워크를 끊고 다시 접속하자 페이지·폴리필이 캐시에서 열렸습니다(헤드리스 크롬). 사무실 PC 크롬에도 6개 파일이 저장됐습니다.

## 8. 트러블슈팅

| 증상 | 원인 | 해결 |
|---|---|---|
| 굽고 나서 시리얼·앱에 아무것도 안 나옴 | 다운로드 모드에 남음(DTR 이 켜진 채 리셋) | USB 를 뺐다 꽂거나, 리셋을 DTR=0·RTS=1 → 둘 다 0 순서로 |
| 포트를 열거나 신호를 바꿀 때 보드가 재부팅됨 | Windows 크롬에서 DTR·RTS 가 하나씩 바뀌며 'DTR 꺼짐·RTS 켜짐'(리셋 조건)을 지나감 | 신호는 **RTS 먼저, DTR 나중**에 내림(실기기 확인: RTS→DTR 만 리셋 없음, 동시·DTR→RTS 는 리셋). 앱은 이 순서를 씀 |
| 리셋 직후 부팅 줄(`c6l-contact-lora id=…`)이 안 보임 | Arduino USB-CDC 가 연결 판정 전 출력을 버림 | 아무 줄이나 보내 상태 응답(`id=… radio=…`)으로 확인 |
| `radio=-2`, OLED `LoRa ERR` | SX1262 초기화 실패(새 모듈 첫 부팅에서 한 번 관찰) | 자동으로 3번 다시 시도. 계속되면 전원을 다시 넣음. 로그 `i2c_fail` 이 0 이 아니면 I2C(확장칩) 문제 |
| 송신기 셋째 줄 `link --`, READY 가 안 뜸 | 수신기 꺼짐, 거리·안테나, 채널 혼잡 | 수신기 전원과 로그 `rx id=…` 확인, 안테나 확인 |
| 앱 칸이 `끊김`·OFF | 송신기 꺼짐 또는 8초 동안 수신 없음 | 송신기 전원·링크 확인 |
| 앱이 "[USB 연결]을 눌러…"에서 칸이 안 채워짐 | 수신기 대신 송신기 포트를 고름(목록 이름이 같음) | [USB 연결]을 다시 눌러 다른 포트를 고름 |
| 앱 "수신기 응답 없음" | 수신기가 USB 는 연결됐지만 상태 줄을 안 보냄(리셋 중·멈춤) | 수신기 USB 를 다시 꽂음 |
| 앱 "이 브라우저는 USB 시리얼을 지원하지 않습니다" | iPad·Safari·Firefox | PC 크롬·엣지, 안드로이드 크롬 |
| 오프라인에서 앱이 안 열림 | 그 기기에서 온라인으로 한 번도 안 열었거나 사이트 데이터를 지움 | 인터넷이 될 때 주소를 한 번 열기(홈 화면에 추가) |
| 송신기 ID 가 바뀜 | 본체 버튼 2초 누름 → 설정 모드 → 저장 | 시리얼 `id N` 이나 버튼으로 다시 정함 |
| 빌드 실패 "국내 KR920 채널만…" / "EIRP 상한…" | 주파수·출력·안테나 이득이 국내 기준 밖 | `FREQ_HZ`·`TX_DBM`·`ANT_GAIN_DBI` 를 기준 안으로 |

## 9. 남은 일·주의

- **안드로이드 태블릿 실기기 시험:** 홈 화면에 추가한 뒤 비행기 모드에서 USB 로 수신기에 붙는지 봅니다.
- **25대 동시 운용:** 동시에 누를 때의 지연과 충돌을 봅니다. 계산상 채널 점유는 약 33%(하트비트 3초) 입니다.
- **수신기 Wi-Fi AP·192.168.4.1 페이지:** 실기기에서 아직 확인하지 않았습니다.
- **규정:** 무선설비규칙 원문과 대조하고, KC 적합성평가 여부를 확인합니다.
- **기존 펌웨어:** 첫 굽기 때 Erase all 로 공장 펌웨어(Meshtastic·데모)를 지웠습니다. 되돌리려면 flasher.meshtastic.org 를 씁니다.
